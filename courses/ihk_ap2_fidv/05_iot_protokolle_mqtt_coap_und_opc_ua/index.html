LF 11: Industrielle IoT-Protokolle (OPC UA, MQTT, CoAP)

OPC UA Informationsmodell & Security, MQTT Pub/Sub (QoS 0/1/2, LWT) & CoAP

📚 Fachwissen & IHK-Prüfungsrelevanz

Für die Vernetzung von Sensoren mit Cloud- und SCADA-Systemen dominieren zwei Protokolle: OPC UA in der Automatisierung und MQTT im Internet of Things.

1. OPC UA (IEC 62541)

OPC Unified Architecture ist ein plattformunabhängiger, serviceorientierter Industriestandard:

  • Informationsmodell: Bildet Daten semantisch in einem objektorientierten Knoten-Graphen (Nodes: Objects, Variables, Methods) ab.
  • Security Architecture: Gegenseitige Authentifizierung via X.509-Zertifikate, Integritätssignatur und AES-Verschlüsselung auf Protokollebene.
  • Kommunikationsmodelle: Client/Server (Request/Response) und Pub/Sub (für hochzyklische Broadcasts).

2. MQTT (Message Queuing Telemetry Transport)

Leichtgewichtiges Publish/Subscribe-Protokoll über TCP (Standardport 1883, TLS Port 8883):

KonzeptFunktionsweise & IHK-Bedeutung
Topic-HierarchieHierarchische Strings mit Wildcards: + (Single-Level) und # (Multi-Level). Bsp.: halle1/linie2/+/temperatur.
QoS 0 (At most once)Feuer & Vergessen (Best Effort, keine Bestätigung).
QoS 1 (At least once)Mindestens einmal (Paket wird wiederholt, bis PUBACK eintrifft; Duplikate möglich).
QoS 2 (Exactly once)Genau einmal (4-Wege-Handshake; maximale Zuverlässigkeit, höhere Latenz).
Last Will & Testament (LWT)Vordefinierte Nachricht, die der Broker publiziert, wenn der Client unerwartet offline geht.

OPC UA: Sicherheitskonzept & Zertifikate 8 Punkte
Ein MES-System (Manufacturing Execution System) soll Prozessdaten von mehreren OPC UA Servern aus der Fertigung auslesen.

a) Welche drei Sicherheitsaspekte werden durch den OPC UA Security Layer standardmäßig abgedeckt (CIA-Triade)? b) Beschreiben Sie den Mechanismus des Trust-Managements beim Verbindungsaufbau zwischen einem OPC UA Client und einem OPC UA Server (Rolle von X.509-Zertifikaten). c) Was passiert, wenn auf dem OPC UA Server die Security Policy 'None' konfiguriert ist, und wie ist dies in Produktionsnetzen zu bewerten?

💡 Offizieller IHK-Erwartungshorizont & Punkteverteilung
a) 1. Vertraulichkeit (Verschlüsselung der Nutzdaten via AES), 2. Integrität (Signatur der Nachrichten via SHA/RSA), 3. Authentizität (Gegenseitige Identifikation von Client und Server via X.509 Zertifikate). b) Client und Server tauschen beim Verbindungsaufbau ihre öffentlichen X.509-Zertifikate aus. Die Verbindung kommt nur zustande, wenn das jeweilige Zertifikat in der 'Trusted'-Liste des Partners hinterlegt ist oder von einer vertrauenswürdigen CA signiert wurde (Reject / Trust Store). c) 'None' bedeutet unverschlüsselte und unsignierte Übertragung im Klartext ohne Authentifizierung. In industriellen Produktionsnetzen stellt dies ein enormes Sicherheitsrisiko dar (Man-in-the-Middle Angriffe, Sabotage von Steuerungswerten) und verstößt gegen gängige Standards wie IEC 62443.
