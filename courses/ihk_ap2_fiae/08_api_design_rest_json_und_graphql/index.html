🌐 API-Design: REST, JSON & GraphQL (LF 11 AE)

Moderne Schnittstellenarchitekturen: RESTful Principles, HTTP-Verben, Idempotenz, Statuscodes, Authentifizierung via JWT/OAuth2 und GraphQL-Konzepte.

1. RESTful Best Practices

- Ressourcen-orientierte URLs: Nomen im Plural (z. B. /api/v1/customers/42/orders). Keine Verben in der URL!
- HTTP-Verben: GET (Lesen), POST (Erstellen), PUT (Vollständiges Ersetzen), PATCH (Teilweises Aktualisieren), DELETE (Löschen).
- Zustandslosigkeit (Statelessness): Jeder Request muss alle nötigen Informationen zur Autorisierung enthalten (z. B. Bearer Token im Authorization Header).

2. REST vs. GraphQL

KriteriumREST APIGraphQL API
EndpunkteViele feste Endpunkte je Ressource (z. B. /users, /orders)Ein einziger universeller HTTP-Endpunkt (z. B. /graphql via POST)
DatenabrufGefahr von Over-Fetching (zu viele Daten) oder Under-Fetching (mehrere Requests)Client spezifiziert exakt die benötigten Felder (kein Over-/Under-Fetching)
CachingSehr einfach über Standard-HTTP-Header (ETag, Cache-Control)Komplexer, da POST-Anfragen nicht nativ gecacht werden
