🧪 Software-Testing & CI/CD-Pipelines (LF 12 AE)

Qualitätssicherung im Software-Lebenszyklus: Teststufen nach ISO 29119, Test-Driven Development (TDD), Mocking-Frameworks, Code Coverage und Continuous Integration / Continuous Deployment (CI/CD).

1. Die Testpyramide nach Mike Cohn

  • Unit-Tests (ca. 70 %): Testen einzelne Methoden und Funktionen isoliert. Externe Abhängigkeiten (DB, Netzwerk) werden durch Mocks/Stubs ersetzt. Ausführung in Millisekunden.
  • Integrationstests (ca. 20 %): Testen das Zusammenspiel mehrerer Komponenten (z. B. Service greift auf echte Test-Datenbank zu oder sendet HTTP-Request).
  • End-to-End (E2E) / UI-Tests (ca. 10 %): Simulieren reale Benutzerinteraktionen im Browser/Client. Langsam, teuer, testen aber den vollständigen Geschäftsprozess.

2. CI/CD-Pipelines: Automatisierter Build & Release

- Continuous Integration (CI): Entwickler mergen Code täglich in den Main-Branch. Automatische Trigger starten Build, Linter, statische Code-Analyse (SonarQube) und alle Unit-/Integrationstests.
- Continuous Delivery / Deployment (CD): Erfolgreich getestete Builds werden automatisch paketiert (z. B. Docker-Image) und auf Staging- oder Produktivumgebungen ausgerollt.
