DNS 08: NS-Delegation, PTR Reverse DNS & FCrDNS

Verstehe Zonen-Delegation mit redundanten Nameservern, die Oktett-Umkehrung in in-addr.arpa und Mailserver-Validierung via FCrDNS.

🔄 1. Reverse DNS & in-addr.arpa

Wie findet man heraus, welcher Server hinter der IP 188.245.100.5 steckt? Über die spezielle Reverse-Lookup-Zone in-addr.arpa:

# Reverse Lookup mit dig:
dig -x 188.245.100.5 +short
# Ausgabe: mail.it-praxisportal.de.

# Was dig im Hintergrund abfragt (Oktette umgekehrt!):
dig 5.100.245.188.in-addr.arpa. PTR

🛡️ 2. Forward-Confirmed Reverse DNS (FCrDNS)

FCrDNS ist der De-facto-Standard für Spam-Schutz im E-Mail-Verkehr:

💡 Warum fast alle Mails ohne PTR im Spam landen

Jeder Serverbetreiber kann im SMTP-Handshake behaupten: HELO mail.google.com. Der empfangende Server prüft die reale IP via PTR-Record und testet anschließend den A-Record. Stimmt die Kette nicht überein, wird die Verbindung sofort abgewiesen!

📑 3. Cheat-Sheet: NS & PTR Syntax

Record-Typ Zweck Syntax-Beispiel
NS Zonen-Delegation firma.de. IN NS ns1.provider.de.
PTR (IPv4) Reverse DNS (IP → Name) 42.2.0.192.in-addr.arpa. IN PTR srv.de.
PTR (IPv6) Reverse DNS (IPv6) 1.0.0.0...b.d.0.1.0.0.2.ip6.arpa. IN PTR srv.de.
