C 03: Strings, Stack vs. Heap & Manuelle Speicherallokation

Tauche ein in das Speichermanagement: Null-terminierte C-Strings ('\0'), Stack vs. Heap Architektur, malloc(), calloc(), realloc(), free() und die Eliminierung von Memory Leaks.

🔤 1. C-Strings & das unsichtbare Null-Byte ('\0')

In C gibt es keinen eingebauten string-Datentyp. Ein C-String ist schlicht ein sequentielles Array aus char-Bytes, das zwingend mit dem ASCII-Wert 0 ('\0', Null-Terminator) endet:

char str[] = "C++"; // Belegt im Speicher 4 Bytes: ['C', '+', '+', '\0']
📍 Speicherlayout eines C-Strings:
Index: [ 0 ] [ 1 ] [ 2 ] [ 3 ]
Zeichen: 'C' '+' '+' '\0' <-- Wichtig: Bestimmt das String-Ende!
Hex: 0x43 0x2B 0x2B 0x00
🛑 Didaktische Analogie: Der Güterzug mit Schlusssignal

Ein C-String gleicht einem Güterzug. Die CPU weiß nicht im Voraus, wie viele Waggons (Buchstaben) angehängt sind. Sie fährt von Waggon zu Waggon, bis sie auf das rote Schlusssignal ('\0') stößt. Fehlt dieses Null-Byte, fährt die CPU ungebremst über fremden Speicher weiter (Buffer Overread)!

🏢 2. Stack vs. Heap: Die Speicherarchitektur

Jedes C-Programm teilt seinen virtuellen Adressraum in klar definierte Segmente auf:

┌────────────────────────────────────────────────────────┐  Hohe Adressen (0x7FFF...)
│ STACK (Automatisch, LIFO, sehr schnell, z.B. 8MB Limit)│  ▼ wächst nach unten
├────────────────────────────────────────────────────────┤
│                       (Freier Raum)                    │
├────────────────────────────────────────────────────────┤
│ HEAP (Dynamischer Speicher, manuell mit malloc/free)  │  ▲ wächst nach oben
├────────────────────────────────────────────────────────┤
│ BSS / DATA (Globale & statische Variablen)             │
├────────────────────────────────────────────────────────┤
│ TEXT SEGMENT (Kompilierter Maschinencode / Read-Only)  │  Niedrige Adressen (0x0000...)
└────────────────────────────────────────────────────────┘
Eigenschaft Stack (Stapelspeicher) Heap (Freispeicher)
Lebensdauer Automatisch an Scope (Funktionsblock {}) gebunden Manuell: Bis free() aufgerufen wird
Größe Fest zur Compile-Zeit / Begrenzt (Stack Overflow bei riesigen Arrays) Dynamisch zur Laufzeit (GBs an RAM)
Verwaltung CPU Stack Pointer Register (0 Overhead) malloc() / calloc() / realloc() / free()

🛠️ 3. Dynamische Speicherallokation & Memory Leaks

Der Lebenszyklus einer Heap-Allokation in C:

#include <stdlib.h>

// 1. Speicher auf dem Heap reservieren (z.B. für 10 Ganzzahlen):
int* buffer = (int*)malloc(10 * sizeof(int));
if (buffer == NULL) {
    // Allokation fehlgeschlagen (Out of Memory)
    return -1;
}

// 2. Speicher verwenden:
buffer[0] = 123;

// 3. Speicher freigeben & Dangling Pointer eliminieren:
free(buffer);
buffer = NULL; // WICHTIG: Verhindert versehentlichen Zugriff nach Freigabe!

💡 Systems Pro-Tipp: calloc vs. malloc

malloc() reserviert rohen, uninitialisierten Speicher (enthält zufälligen Datensalat/Garbage). calloc(n, size) setzt alle Bits garantiert auf 0!
