2. 🏛️ Die Architektur: Model-View-Controller (MVC)

In professionellen Software-Unternehmen schreibt man niemals Geschäftslogik und Benutzeroberfläche in einen einzigen großen Code-Klotz ("Spaghetti-Code"). Stattdessen trennt man das System strikt nach dem MVC-Muster:

1. Das Model (Daten & Logik)

Klassen Tier & Tierheim

Verwaltet alle Tiere, berechnet Statistiken (Ø Alter, Gewicht), filtert Bestände und speichert/lädt JSON & CSV.

💡 100% Headless testbar: Weiß nichts von Tkinter und läuft komplett ohne Bildschirm!
2. Die View (Anzeige)

Tkinter Widgets

Das visuelle Fenster: Header, Formular-Eingabefelder, Listbox für den Tierbestand, Aktionsbuttons und die dynamische Statusleiste.

👀 Dumb View: Zeigt nur an, was das Model ihr mitteilt.
3. Der Controller (Steuerung)

Klasse TierheimApp

Reagiert auf Benutzerklicks, validiert Eingaben mit try-except, ruft Methoden des Tierheims auf und aktualisiert die Anzeige.

🛡️ Fehler-Abfangjäger: Verhindert App-Abstürze bei Fehleingaben.
🍽️ Die Restaurant-Analogie für MVC:
  • Model (Die Küche): Kocht das Essen, verwaltet die Zutaten und Rezepte (Logik & Daten).
  • View (Die Speisekarte & Teller): Das, was der Gast sieht und liest (Grafik).
  • Controller (Der Kellner): Nimmt die Bestellung vom Gast auf, gibt sie an die Küche weiter und bringt das fertige Gericht an den Tisch!

3. 🧬 Das Datenmodell: Vererbung & Polymorphie

Ein Tierheim beherbergt verschiedene Tierarten: Hunde, Katzen und Vögel. Sie alle teilen gemeinsame Eigenschaften (Name, Alter, Gewicht, Impfstatus, Hunger), besitzen jedoch jeweils eigene Spezialmerkmale und Verhaltensweisen:

Python (Vererbungshierarchie & super()) 
class Tier:
    def __init__(self, name: str, alter: int, gewicht: float, geimpft: bool = False, hunger: int = 50):
        if not name.strip():
            raise ValidierungsFehler("Name darf nicht leer sein!")
        self.name = name.strip()
        self.alter = alter
        self.gewicht = gewicht
        self.geimpft = geimpft
        self.hunger = max(0, min(100, hunger))

    def mache_laut(self) -> str:
        return f"{self.name} macht ein Geräusch."

class Hund(Tier):
    def __init__(self, name: str, alter: int, gewicht: float, rasse: str = "Mischling", ...):
        super().__init__(name, alter, gewicht, ...)
        self.rasse = rasse
        self.gassigegangen = False

    def mache_laut(self) -> str:
        return f"{self.name} bellt: Wuff! Wuff! 🐶"
🎭 Polymorphie in der Praxis:
Wenn wir im Tierheim for tier in self.tiere: print(tier.mache_laut()) aufrufen, weiß Python dank Polymorphie zur Laufzeit automatisch, welches Tier welchen Laut von sich gibt – ohne eine einzige if/elif-Typabfrage!

4. 💾 Savegame-Persistenz mit dem Factory-Muster

Beim Speichern als JSON-Datei wandeln wir jedes Tier-Objekt in ein Dictionary um und ergänzen den Schlüssel "art": "Hund". Beim Laden liest die Factory-Methode Tier.from_dict(data) diesen Schlüssel aus und erzeugt automatisch die exakte Unterklasse:

Python (Factory-Methode mit Type-Discriminator) 
@classmethod
def from_dict(cls, data: dict) -> Tier:
    art = data.get("art", "Tier")
    if art == "Hund":
        return Hund(name=data["name"], alter=data["alter"], gewicht=data["gewicht"], rasse=data.get("rasse", "Mischling"), ...)
    elif art == "Katze":
        return Katze(...)
    elif art == "Vogel":
        return Vogel(...)
    else:
        return Tier(...)

6. 💡 Ausklappbare Hilfestellungen & Tipps

🔍 Tipp zu Schritt 1: Eigene Exceptions definieren

Eigene Exception-Klassen erben in Python einfach von Exception oder einer übergeordneten Basis-Exception:

class TierheimFehler(Exception):
    pass

class ValidierungsFehler(TierheimFehler):
    pass
🔍 Tipp zu Schritt 4: CSV-Export mit dem csv-Modul

Nutze csv.writer mit newline="" für saubere Tabellenausgabe:

with open(dateipfad, "w", newline="", encoding="utf-8") as f:
    writer = csv.writer(f)
    writer.writerow(["Art", "Name", "Alter", "Gewicht", "Geimpft", "Hunger", "Details"])
    for t in self.tiere:
        writer.writerow([t.__class__.__name__, t.name, t.alter, f"{t.gewicht:.1f}", "Ja" if t.geimpft else "Nein", f"{t.hunger}%", t.get_details()])
🔍 Tipp zu Schritt 5: Fehler im GUI-Controller sanft abfangen

Damit die Desktop-App bei einer Fehleingabe nicht abstürzt, fange Exceptions im Event-Handler ab:

try:
    self.tierheim.tier_aufnehmen(neues_tier)
    self.aktualisiere_ansicht()
    self.setze_status(f"{neues_tier.name} aufgenommen! 🎉", typ="success")
except TierheimFehler as e:
    self.setze_status(str(e), typ="warning")
